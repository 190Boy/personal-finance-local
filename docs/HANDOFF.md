## 模組責任
web/app.mjs：事件、敏感資料生命週期、結果顯示與下載；不應放銀行專屬座標規則。
pdf-parser/extract.mjs：PDF.js／Worker、大小和資源上限、文字與座標；不應加入網路上傳。
pdf-parser/parser.mjs：表頭辨識、欄位分配、日期／金額校驗、跨頁與餘額核對。現為共用表格機制與銀行識別／格式提示，仍須依兩家實際 PDF 校正；不能稱已支援所有中信、玉山格式。
pdf-parser/export.mjs：預覽匯出與 CSV 公式防護。
web/vendor/pdfjs：固定完整版本，更新時必須成套更新並重測。
tools：本機只讀伺服器。執行網站不需要 npm 套件安裝。

## 需要後續校正的重點
交易表頭各欄 x 中心、金額靠右對齊、同一列被拆成多個文字項目、跨頁續行、重複表頭、頁尾、日期時間換行。
目前沒有固定猜測座標、無根據銀行樣本硬寫數值、用餘額反推金額，或 OCR／多帳戶／多幣別處理。遇到無法定位時保留可見錯誤而非自動入帳。
相同日期／時間／摘要／金額／餘額不一定是同一筆經濟事件，所以候選只標記、不直接刪除。

## 開發順序
先完成兩家實際銀行樣本在 Windows Chrome、iPhone Safari 的逐欄及餘額驗收。
通過後：Google OAuth → 每人 Drive／Sheets → 資產總覽與正式記帳 → 合法資料來源同步。
公開前端不等於共用後端：不能讓所有人透過開發者身分 GAS 寫到同一份資料庫。背景排程需另行規劃每位使用者的合法授權。
信用卡消費／繳款、轉帳、股票買賣、股利、發票／外送收據重複與退款都需要明確會計規則及人工核對；此版不宣稱已完成。
