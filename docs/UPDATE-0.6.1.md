# v0.6.1：共用匯入紀錄、雲端歷史與匯入入口

## 本次決定
保留股票快照與股票庫存／異動的關聯。快照記錄「券商帳戶、報表時間、持股筆數、總市值、內容指紋」，是完整庫存的批次索引，讓首頁選最新的一整份庫存，避免舊股票殘留、重複累加，並區別同時間衝突。必須保存快照識別與時間；分成獨立工作表是目前實作方式，不是所有系統唯一做法。它與「匯入紀錄」不同：前者是資產狀態，後者是操作與排重追溯。

銀行待核對交易照常存入 Sheets，不增加確認閘門，不刪掉不完整交易；首頁餘額既有核對規則仍維持。股票人工確認流程亦維持。

## 共用匯入紀錄與遷移
銀行與股票都寫入「匯入紀錄」，以「類別」區分銀行存款／股票資產；來源欄可放銀行或券商。欄位為：
匯入 ID、來源、帳戶代稱、類別、寫入時間、來源筆數、新增筆數、庫存檔指紋、異動檔指紋、核對狀態。

首次成功連接新版、重新載入雲端或儲存時，會辨識原七欄銀行紀錄，僅更新表頭並保留既有列；股票舊紀錄按匯入 ID 追加到共用表，保留檔案指紋與核對狀態。舊股票紀錄沒有筆數，因此遷移列的筆數留空，不編造。相同 ID 不重搬。

遷移的表頭、追加與隱藏舊表放在同一個 Sheets batchUpdate；失敗不會只搬一部分。舊「股票匯入紀錄」不刪除，成功後隱藏作歷史備份，新版不再寫入。使用者可在 Sheets 取消隱藏查閱。自訂／不符已知版本的欄名會停止，避免覆寫未知資料。兩裝置同時遷移同批資料以批次標記避免重做，仍不能將不同範圍的併發寫入視為嚴格唯一性保證。舊版客戶端可能仍寫舊頁或因新欄名而停止；請所有裝置更新並依序匯入，不混用舊版。

## 雲端歷史交易
Google 連接成功、手動重新載入及銀行／股票儲存完成時，讀取原「銀行存款」與「股票異動」。交易明細頁上方是雲端歷史，下方保留本次銀行匯入預覽。

可篩選類別、來源帳戶、日期區間、摘要／證券代號／待核對文字；每次顯示 100 筆，可繼續載入顯示。銀行支出／收入單位元，股票提出／存入／結存單位股，不合計成現金收支。待核對銀行列照常顯示，日期缺少的列在未篩日期時仍保留。

相同類別、穩定 ID 與財務／核對內容的重複實體列僅合併顯示，並標示合併數；不刪原 Sheets 列。相同 ID 內容不同全部保留並標示衝突。不同 ID、缺 ID、同日同額等無法確認重複的列不自動刪除。這只是讀取端保護，不表示跨裝置寫入競態已修復。首頁銀行餘額算法不在此版調整。

每個工作表最多讀取 100,000 筆資料（不含表頭）；超過明確報錯，不悄悄截斷或宣稱完整。表格只是日期／時間的顯示排序，不拿此排序猜測同日交易的實際先後或重算餘額。登出、帳號切換與離開會清空歷史；歷史、篩選輸入與交易不寫入 localStorage 或 SW，重新開啟需連接 Google。

## 匯入入口
下方導覽改「匯入」：
- #import：選銀行存款或股票資產。
- #bank-import：原本中信 PDF／玉山 Excel 表單。
- #stocks：原本股票 B／C PDF 表單。
既有解析、密碼處理、欄位設定、自動儲存與股票人工確認流程不改。首頁與空白預覽入口都先到選擇頁；直接股票連結仍可用。

## 跨裝置排重建議（規劃，非嚴格防重已完成）
1. 固定帳戶識別：未來用內部 accountId，代稱僅供顯示，避免改名變成新帳戶。目前仍須每次用相同代稱。
2. 分開檔案／批次 ID 與交易 ID。檔案 hash 擋同檔；交易 ID 不依賴檔名或匯入時間，優先用來源交易序號。沒有序號時用來源、帳戶、日期時間、原始金額、費用、交易後餘額及保守正規化摘要，保留同檔重複出現次數。銀行與股票的 ID 命名空間分開。
3. 寫入前重新讀取最新 ID 集合，維持現在的重試與批次紀錄。成功後再檢查並在讀取端合併相同 ID／內容；不以「同日同額」直接刪交易。內容衝突、部分區間無法判斷的候選保留人工核對，符合不要漏資料的原則。
4. 真正要保證兩裝置同時寫不同重疊批次也不重複，需要所有寫入都經同一個每使用者協調器／序列佇列與冪等索引，另規劃授權、重試、過期鎖及中途斷線恢復；不得只靠瀏覽器 localStorage 鎖或 Sheets「先讀再 append」宣稱保證。若採後端，只存必要的協調狀態，財務資料仍在各人 Sheets，原始 PDF／密碼仍不傳；此版不新增後端或共同財務資料庫。
建議小範圍先用既有寫入比對＋本版歷史合併顯示，遇疑似重複保留、不要自動刪。嚴格寫入協調另做獨立版本。

依 Google 官方文件，batchUpdate 能使同一批請求一起成功或失敗；這不等同本應用程式已完成不同裝置之間的讀取、比對、寫入協調：
https://developers.google.com/workspace/sheets/api/guides/batchupdate
