# v0.7.1：最新帳單消費與淨資產估算、信用卡金額改元

## 使用者操作

1. 關閉所有舊網站與主畫面 PWA 視窗，重新開啟並確認右上角 v0.7.1。仍顯示舊版時，設定清除公開程式快取後，再關閉全部視窗重開。
2. 重新連接 Google，或按重新載入雲端資料。已同步的信用卡明細可直接計算，無須重匯。
3. 新匯入只須填穩定帳戶代稱、正確帳單月份並同意同步；完整帳單資訊收在選填區，不影響消費合計。

## 首頁計算

每個銀行／帳戶代稱各取最新的有效帳單月份，只加總種類恰好是「消費」的明細，顯示帳單月份、金額、筆數和最後匯入日期。不同銀行／帳戶月份可能不同，各自列明；較舊月份不累加。繳款、退款、費用、分期當期與待核對均不參與這個特定合計，亦不拿明細淨額代替消費加總。

同ID、相同金額與種類的重複列只計一次；同ID金額／種類衝突、消費金額不合法時保留原列並標示未列入。最新月份沒有明細時標示缺漏，不退回舊月份，也不顯示成已確認零欠款。合法零消費月份可以顯示0。

淨資產顯示為估算：已載入銀行存款＋已載入股票報表市值－各信用卡帳戶最新月份消費合計。可以為負數；沒有任何已載入來源則不顯示0。來源缺漏、讀取失敗或待核對會標示部分範圍，各來源日期分別顯示。資產圓餅仍只呈現正值銀行／股票資產。

消費合計不是銀行已確認待繳；未扣已繳款或退款，也沒有加上其他費用、未來分期及其他負債，因此估算淨資產不代表完整／即時實際淨資產。原本人工確認的完整帳單資訊繼續保存，但不作為這版首頁計算來源。

## 信用卡試算表單位升級

舊欄名「臺幣金額分、帳單總額分、結帳後已繳金額分」原以整數分保存，試算表顯示12345.00容易被誤讀成12345元。新欄名改「臺幣金額（元）、帳單總額（元）、結帳後已繳金額（元）」，新值為123.45，格式為#,##0.00。程式內部仍用整數分計算，讀寫時明確轉換。

新版本連接時自動將既有信用卡表三個金額欄從分除以100，與表頭、格式及版本標記一起原子寫入。依表頭辨識，僅轉換一次；空值保持空、負值保留，交易ID、匯入紀錄與其他欄位不變。金額無法安全辨識／轉回時停止，不猜測、更不只改表頭。不要自行先除100或手動改欄名，以免失去單位辨識。

銀行、股票工作表單位不更動。沒有新增工作表或重匯實際交易。

## 協調與舊版保護

沿用協調版本的原子批次重試。單位升級同批建立fw2的特殊schema barrier（metadataId=2000000000、metadataValue=cards-yuan-v1）。v0.7.1明確識別此標記；v0.7.0及以前協調器會拒絕寫入，避免舊版將整數分寫進新元欄位。不得手動刪除此標記來繞過版本保護；所有裝置都需更新，舊版同步可能顯示標記／同步異常。已有舊版進行中的批次會被原子版本衝突拒絕，或在升級之前完成並一併轉換。

## 維護位置與驗證

cloud/credit-cards.mjs：cardSummary月消費彙總、cardTable讀取已知單位、cardSheetRows轉元；confirmedCardSummary保留歷史人工確認規則，首頁不呼叫。
cloud/google.mjs：cardCurrency原子升級與舊版寫入保護，saveCards寫入元／summary讀回整數分。
web/assets.mjs：月份與估算淨資產；web/index.html、web/cards.mjs：可選帳單資訊。

測試包含最新月份／多帳戶、種類篩選、重複與衝突、零消費、元分精確往返、失敗不改表、兩裝置遷移與匯入、舊版保護、負淨資產、缺漏範圍，以及Chrome完整匯入／首頁／歷史／重登流程。實際Google帳戶與iPhoneSafari/PWA仍需使用者驗收；桌面手機寬度模擬不等於iPhone實機。
