# 我的理財（personal-finance-local）

在手機或電腦瀏覽器裡讀取銀行、券商、信用卡下載的對帳檔，整理成交易明細與資產總覽，並存進使用者自己 Google Drive 裡的一份試算表。純前端 PWA，部署在 GitHub Pages，沒有後端伺服器。

目前版本：v0.11.0。各版本改了什麼見 [CHANGELOG.md](CHANGELOG.md)。

## 功能

### 支援的匯入來源

| 類別 | 來源 | 檔案 | 說明 |
| --- | --- | --- | --- |
| 銀行存款 | 中國信託銀行 | PDF | 本機用 PDF.js 解密，需輸入 PDF 開啟密碼 |
| 銀行存款 | 玉山銀行 | Excel（.xls／.xlsx） | 支援加密 XLSX，本機解密 |
| 股票 | 中國信託證券／集保 | PDF | 證券存摺庫存（必要）與登摺資料（選用） |
| 信用卡 | 凱基銀行 | Excel | 帳單與未出帳明細皆可 |
| 信用卡 | 中國信託銀行 | CSV | 帳單明細與未出帳單明細皆可，自動辨識 UTF-8／Big5 |
| 雲端發票 | 財政部電子發票整合服務平台 | CSV | 載具消費明細，含每張發票的品項 |
| LINE Pay | LINE「LINE錢包」聊天室 | 文字檔 | 聊天室 → 設定 → 傳送聊天紀錄；含付款、儲值通知與錢包餘額 |

所有檔案與密碼都只在瀏覽器裡處理，不會上傳。解析結果會逐筆顯示供人工核對；欄位對不上、餘額不連續、金額方向不合理的列會標成「待核對」，不會被靜默刪除或自動修正，也不會用餘額倒推金額。

### 頁面

- **首頁**：銀行存款合計、股票市值、各信用卡最新帳單月份的消費合計、估算淨資產，以及銀行／股票的資產占比圖。
- **交易明細**：從試算表載入的銀行、股票、信用卡紀錄，可篩選；手機顯示卡片，桌面顯示表格。
- **發票配對**：從交易明細進入。把雲端發票和信用卡、銀行紀錄對起來，配到後在交易明細可以看到那筆消費買了哪些品項；配不到的依付款習慣讓你確認付款方式。也會列出 LINE 錢包餘額對不上的地方（沒有通知的好友轉帳等）讓你標記。
- **手動記帳**：從交易明細進入。補記現金消費、LINE Pay 轉帳等沒有檔案可匯入的收支，可修改、刪除；從錢包餘額落差點「補記明細」會自動帶入金額與日期。
- **匯入**：先選資料種類（銀行存款／股票／信用卡／雲端發票／LINE Pay），再選來源與檔案。
- **設定**：Google 連接與登出、清除公開程式快取、iPhone 加入主畫面說明。

### 首頁數字怎麼算

- **銀行存款**：每個銀行／帳戶代稱取最新一筆交易的餘額。同日跨來源先後不明或餘額對不上的帳戶會另列待確認。
- **股票**：每個券商帳戶取最新一份完整庫存快照的報表市值（收盤價，非即時行情），不計成本與損益。
- **信用卡**：每個帳戶取最新帳單月份，只加總種類為「消費」的明細；繳款、退款、費用、分期不列入。
- **估算淨資產** = 銀行存款 + 股票市值 − 信用卡最新月份消費合計。這是估算，不含未出帳、未來分期與其他負債；有來源缺漏時會標示涵蓋範圍。

## 資料存在哪裡

連接 Google 後，工具會在你自己的 Drive 建立一份試算表，只申請 `drive.file` 權限，也就是只能存取這個工具自己建立的檔案。試算表不會分享給任何人。

| 工作表 | 內容 |
| --- | --- |
| 銀行存款 | 銀行交易明細 |
| 股票庫存 | 股票快照與每檔持股 |
| 股票異動 | 證券存摺的股數異動 |
| 信用卡 | 信用卡帳單與明細（金額以元為單位） |
| 發票 | 雲端發票與品項，以「資料類型」區分；金額以元為單位 |
| LINE Pay | LINE 錢包聊天室裡的付款、儲值、提領與取消通知 |
| 手動記帳 | 手動補記的收支；修改、刪除都新增一列，以最新為準 |
| 配對紀錄 | 你在發票配對頁按下的每個決定（配對、付款方式、儲值等），只增不改，以最新一筆為準 |
| 付款習慣 | 店家通常的付款方式，例如全家用 LINE Pay 錢包；第一次確認配對時建立，可直接在試算表修改 |
| 匯入紀錄 | 每次匯入的來源、筆數與核對狀態，所有類別共用 |

舊版留下的「股票快照」「股票匯入紀錄」已合併進上面的工作表，原頁隱藏保留，不要刪除。

另外試算表裡有少量程式用的協調標記（Developer Metadata），用來避免兩台裝置同時寫入時資料重複，會自動清理，不需要手動處理。

- Google 授權 Token、交易資料、銀行檔案與密碼都不會存進 localStorage、Cookie 或離線快取；離開頁面就清除。
- 唯一存在瀏覽器裡的個人資料，是設定頁勾選「在這台裝置記住帳號」後保存的電子郵件，用來在下次登入時預先帶入。共用裝置不要勾選。
- 銀行存款在勾選自動儲存時，解析完成會直接同步；股票與信用卡需要人工確認後才同步。

## 已知限制

- iPhone Safari／主畫面 PWA、Android，以及真實 Google 帳號的同步流程，仍待實機逐項驗收；目前的自動測試使用模擬的 Google API。
- 只支援文字型 PDF、單一帳戶、新台幣；沒有 OCR、多幣別、外幣換匯。
- 不同匯出檔裡「同日、同額、同摘要」的兩筆真實交易無法可靠區分，請核對原檔。
- 銀行的卡費扣款與信用卡繳款不會自動互相配對。
- 發票配對只影響交易明細的顯示，首頁的支出合計與淨資產還沒有使用配對結果。
- 沒有發票、也沒有卡片或銀行紀錄的消費（夜市現金、轉帳給朋友等），要用「手動記帳」補上。

## 開發

需要 Node.js 22 以上，不需要 `npm install`。

```
npm start             # 本機伺服器 http://127.0.0.1:4173/web/
npm test              # 單元測試
npm run format        # 用 Prettier 統一排版
npm run build:pwa     # 重新產生 sw.js（改了任何公開檔案都要跑）
```

合併到 `main` 就會直接發布到 GitHub Pages。部署步驟、更新後如何確認手機拿到新版，見 [docs/DEPLOY.md](docs/DEPLOY.md)。

瀏覽器端到端測試在 `tests/*.cjs`，需要 Playwright 與 Windows 上的 Chrome，並只使用合成資料與模擬的 Google API。

### 程式結構

| 目錄 | 負責 |
| --- | --- |
| `web/` | 介面：`app.mjs`（銀行匯入流程）、`stocks.mjs`、`cards.mjs`、`invoices.mjs`、`matching.mjs`、`history.mjs`（交易明細）、`assets.mjs`（首頁合計與淨資產）、`pwa.mjs` |
| `pdf-parser/` | 本機解析：PDF 文字座標擷取與表頭定位（`extract`、`geometry`、`parser`）、Excel 讀取與解密（`excel*`、`tabular`）、股票 PDF、信用卡檔案、雲端發票 CSV（`invoices`）、CSV／JSON 匯出 |
| `cloud/` | Google 連接與試算表讀寫：`google.mjs`（寫入協調與原子批次）、`records.mjs`、`stocks.mjs`、`credit-cards.mjs`、`invoices.mjs`（各類別欄位與彙總）、`matching.mjs`（發票配對規則）、`dedup.mjs`（排重） |
| `web/vendor/` | 自行託管的 PDF.js 6.4.299、SheetJS、officecrypto-tool，不使用外部 CDN |
| `tools/` | 本機伺服器、`sw.js` 產生器、officecrypto 重建腳本 |
| `tests/` | 單元測試（`*.test.mjs`）與瀏覽器測試（`*.cjs`） |
